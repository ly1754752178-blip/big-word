# 雪花式放射技能树布局设计

## 背景

当前 `SkillTreeView.tsx` 使用混合式径向树布局：根节点居中，大节点环形分布，普通子节点沿父节点方向做弧形散开。该布局在节点增多、层级加深时容易出现分支方向混乱、节点重叠、子节点横向排列等问题，与参考图要求的「雪花/魔法阵」风格差距较大。

本次设计将布局算法完全替换为「雪花式放射技能树（Snowflake Radial Skill Tree）」生成器，使其能够：

1. 严格按参考图规则自动生长技能树。
2. 支持任意层级展开/收拢，不重叠、不越界。
3. 便于未来整体移植到后端，批量生成新技能树坐标。
4. 新增技能只需按文件模板填写 `parentIds`，无需手写坐标。

---

## 目标

- 重新设计 `SkillTreeView.tsx` 的布局算法，不影响其他模块。
- 实现一个纯函数式生成器 `generateSnowflakeLayout(nodes, expandedIds)`。
- 保留旧交互：点击节点展开下一级，再次点击收拢整棵子树。
- 节点详情从节点上方浮动弹出，改为右上角固定玻璃面板。
- 提供文件化导入模板，方便本地批量新增技能树。

---

## 术语

| 术语 | 含义 |
|------|------|
| A 节点 | 技能总等级核心节点，位于技能树中心，不可加点 |
| B 节点 | 一级技能节点，直接挂在 A 下 |
| C 节点 | 二级技能节点，挂在 B 下 |
| D/E/F… | 更低级技能节点，递归延伸 |
| 小型放射中心 | 某个节点的子节点数量 ≥4 时，该节点自身成为局部放射中心 |
| 扇区 | 某个父节点分配给其子节点的可用角度范围 |

---

## 一、算法架构

### 1.1 纯函数接口

```ts
type SnowflakeLayout = {
  nodes: Array<SkillNode & { pos: { x: number; y: number } }>;
  bounds: { minX: number; maxX: number; minY: number; maxY: number };
};

function generateSnowflakeLayout(
  nodes: SkillNode[],
  expandedIds: Set<string>
): SnowflakeLayout;
```

该函数只依赖 TypeScript 类型与数学运算，不依赖 React / DOM / 浏览器 API，可直接复制到后端使用。

### 1.2 算法步骤

1. **构建邻接表**：读取每个节点的 `parentIds[0]`，建立 `parentId -> children[]`。
2. **计算可见节点**：节点可见当且仅当其到 A 的整条祖先链都在 `expandedIds` 中。A 默认始终展开。
3. **递归极坐标布局**：
   - A 固定在 `(CX, CY)`。
   - 其他节点位置 = 父节点位置 + 方向 × 层级距离。
   - 方向由该节点被分配到的扇区中心决定。
4. **扇区分配**：父节点按子节点可见子树大小比例划分自己的扇区。
5. **子节点形态**：
   - 1 个子节点：沿父节点方向继续向外。
   - 2 个子节点：以父节点方向为轴左右对称 Y 形分叉。
   - 3 个子节点：在扇区内以父节点方向为中心均匀扇开。
   - ≥4 个子节点：父节点升级为小型放射中心，子节点在围绕父节点的小圆上、限制在当前扇区范围内均匀分布。
6. **输出边界框**：返回所有可见节点坐标及整体边界框，供自适应缩放使用。

### 1.3 小型放射中心处理

当某节点子节点 ≥4 时：

- 子节点到父节点的距离短于普通层级距离，形成紧凑花簇。
- 子节点角度在当前扇区范围内均匀分布，避免侵入相邻主分支。
- 这些子节点自身若还有子节点，则继续在其分配到的子扇区内递归布局。

## 二、展开/收拢状态机

### 2.1 状态

将当前单一 `expId: string | null` 改为 `expandedIds: Set<string>`，支持 B、C、D 多级同时展开。

### 2.2 点击行为

| 节点状态 | 行为 |
|----------|------|
| 无子节点 | 仅选中，在右上角玻璃面板显示详情 |
| 未展开 | 加入 `expandedIds`，显示直接子节点 |
| 已展开 | 从 `expandedIds` 移除该节点，并递归移除其所有后代节点，整棵子树收起 |

### 2.3 典型流程

1. 初始：A 始终展开，B1~Bn 可见，C/D 隐藏。
2. 点击 B3：B3 展开，C31/C32 出现。
3. 点击 C31：C31 展开，D311/D312 出现；B3 保持展开。
4. 再次点击 B3：B3、C31、D311/D312 全部收拢。

---

## 三、自适应缩放与防重叠

### 3.1 边界框计算

`generateSnowflakeLayout` 在计算坐标的同时，统计所有可见节点（含文字标签大致高度）的最小/最大 x、y，输出 `bounds`。

### 3.2 自动缩放平移

每次 `expandedIds` 变化后：

- `targetZoom = min(容器宽 / 边界宽, 容器高 / 边界高) × 留边系数`
- `pan` 使边界框中心对齐容器中心
- 用 `requestAnimationFrame` 做 300–500ms 缓动过渡

### 3.3 防重叠策略

- 扇区按子树可见大小比例分配，大分支获得更多空间。
- 层级距离按深度递增，深层节点自然外推。
- 小型放射中心缩短子节点距离，保持紧凑。
- 任何子节点的扇区绝对不超过父节点扇区，防止回折侵入其他分支。

## 四、与现有代码集成

### 4.1 修改范围

主要改动：

- `src/components/overlays/SkillsOverlay/SkillTreeView.tsx`
- 新增 `src/lib/skillTreeLayout.ts`
- 调整 `src/components/overlays/SkillsOverlay/SkillNodeDetail.tsx` 为固定玻璃面板

### 4.2 不改动的地方

- `SkillTree` / `SkillNode` 类型定义。
- `SkillsOverlay/index.tsx` 总览/详情切换。
- 技能数据的 `parentIds` 关系。
- 滚轮缩放、拖拽平移、双击回根交互。

### 4.3 节点大小

颜色保持现有配色，只按层级调整半径：

| 层级 | 大小 |
|------|------|
| A | 最大 |
| B | 次大 |
| C | 中等 |
| D/E/F… | 最小 |

### 4.4 连线

父子可见节点之间用**单一直线**连接，节点中心到节点中心。移除旧版「主干+分叉」折线，因为规则禁止弯折。

## 五、右上角玻璃详情面板

- 固定在技能树界面右上角，玻璃拟态风格。
- 点击节点后显示该节点名称、等级/最大等级、描述、解锁状态、升级条件/按钮。
- 未选中节点时显示当前技能树概览或保持收起。
- 不跟随节点移动，避免遮挡技能树主体。

## 六、新增技能的文件化导入方式

### 6.1 目录结构

```
src/data/skills/
├── index.ts          # 统一导出
├── cooking.ts        # 料理
├── cleaning.ts       # 打扫
├── programming.ts    # 编程
├── magic.ts          # 魔术
└── _template.ts      # 新增时复制的模板
```

### 6.2 单文件格式

```ts
import type { SkillTree } from '@/types';

export const cookingSkillTree: SkillTree = {
  id: 'cooking',
  name: '料理',
  icon: 'utensils-crossed',
  category: 'daily',
  level: 1,
  maxLevel: 10,
  exp: 0,
  maxExp: 1000,
  skillPoints: 0,
  nodes: [
    {
      id: 'ck-root',
      name: '厨艺',
      description: '料理技能的核心',
      level: 1,
      maxLevel: 3,
      unlocked: true,
      icon: 'chef-hat',
      parentIds: [],
    },
    // B/C/D… 节点，按层级填写 parentIds
  ],
};
```

**不需要填写 `position`**，坐标由布局算法自动生成。

### 6.3 新增步骤

1. 复制 `_template.ts` 为新文件，如 `gardening.ts`。
2. 按层级填写 `parentIds`。
3. 在 `src/data/skills/index.ts` 导出：
   ```ts
   export { gardeningSkillTree } from './gardening';
   ```
4. 在 `mockData.ts` 对应分类数组中加入该技能树。

### 6.4 运行时生成 vs 后端预生成

- 默认使用**运行时生成**：玩家点开某个技能树时才计算该树坐标，其他树不计算。
- 单个技能树节点通常在 20–200 之间，计算耗时 <1ms，不会卡顿。
- 未来若有后端，可直接把 `skillTreeLayout.ts` 复制过去，导入时批量生成坐标存库。

## 七、视觉自检清单

实现后通过浏览器实际渲染逐项检查：

### 结构

- [ ] A 固定在画面中心。
- [ ] B 围绕 A 均匀放射。
- [ ] B → C 沿 B 方向直线延展，不突然转弯。
- [ ] C → D 为同方向延展或 Y 形分叉，无横向排列。
- [ ] ≥4 子节点形成小型放射花，<4 子节点做简单分叉。

### 展开/收拢

- [ ] 初始只显示 A 和 B。
- [ ] 点击 B 展开 C，再次点击 B 收起整棵子树。
- [ ] 展开 B 后再展开 C，B 保持展开。
- [ ] 在 C 展开时点击 B，C、D 一并收起。

### 防重叠与自适应

- [ ] 每次展开/收拢后整棵树完整显示在屏幕内。
- [ ] 节点与文字标签无重叠。
- [ ] 多次切换后无节点飘出可视区域。

### 玻璃面板

- [ ] 点击节点后右上角玻璃面板显示详情。
- [ ] 面板不遮挡技能树主体。

### 不同数据形态

- [ ] 用「料理」大树测试多分支、深层级。
- [ ] 用「打扫/编程/魔术」小树测试基础形态。
- [ ] 临时构造 1/2/3/8 个 B 的测试数据，验证对称性。

### 风险

|------|----------|
| 单个技能树节点极多导致计算耗时 | 实测 200 节点 <1ms；若未来单树破千，可改为后端预生成 |

- `generateSnowflakeLayout` 能根据任意 `parentIds` 结构生成符合参考图的雪花放射布局。

- 节点无重叠、不被遮挡、始终完整可见。
- 节点详情显示在右上角玻璃面板。
- 新增技能树只需按模板填写 `parentIds`，无需手写坐标。
